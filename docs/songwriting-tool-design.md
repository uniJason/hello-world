# 歌曲词曲学习与 AI 辅助创作工具 · 设计方案

> 目标：做一个帮助你**快速学习指定歌曲的词曲创作特点**，把风格、技巧、节奏、
> 韵律等一系列特性总结下来，并借助 AI 工具**创作新的词曲**的学习型工具。

本文档给出一个从 0 到 1 的可落地建议，包含目标场景、核心模块、技术选型、
系统架构、MVP 路线图，以及必要的版权/合规提示。

---

## 1. 目标与用户场景

**核心用户**：想系统学习词曲创作的初学者 / 词曲爱好者 / 独立音乐人。

**典型使用流程**：

1. 用户输入一首歌（歌名 + 艺人，或上传音频 / 歌词文本 / MIDI / 乐谱）。
2. 工具自动做**词的分析**（主题、韵脚、句式、修辞、意象、情感曲线）
   和**曲的分析**（调式、和弦进行、曲式结构、节奏型、旋律轮廓、音域）。
3. 工具输出一份**"风格档案（Style Card）"**——把这首歌可复用的创作技巧
   结构化地总结出来。
4. 用户基于这个风格档案，用 AI 辅助**生成新的歌词 / 旋律 / demo**，
   并可以对比参考曲，迭代修改。
5. 用户把学到的技巧沉淀到个人"技巧库 / 灵感库"里，长期积累。

---

## 2. 核心功能模块

### 2.1 输入与素材管理
- 支持输入形式：歌名+艺人（自动抓取歌词）、纯歌词文本、音频文件
  （mp3/wav）、MIDI、MusicXML、简谱/五线谱截图（OCR 可选）。
- 素材库：按"艺人 / 风格 / 语言 / 情感"打标签，便于后续对比。

### 2.2 歌词分析（Lyrics Analysis）
- **分词与句式**：中文用 `jieba` / `pkuseg`，英文用 `spaCy`。统计句长、
  段落结构（主歌 / 副歌 / bridge）。
- **韵律**：
  - 中文：提取每句尾字的**拼音韵母**（`pypinyin`），标注押韵规律
    （aabb / abab / 通押 / 转韵）、平仄。
  - 英文：用 `pronouncing`（基于 CMU 词典）分析韵脚、音节数、重音模式。
- **修辞与意象**：TF-IDF / KeyBERT 提取关键意象词；用 LLM 做比喻、
  拟人、通感等修辞识别。
- **情感曲线**：按句/段做情感打分（`SnowNLP` / `cnsenti` / HuggingFace
  中文情感模型），画出全曲情绪走向。
- **主题与叙事视角**：LLM 概括主题，识别第一/第二/第三人称、时间线。

### 2.3 曲谱 / 音频分析（Music Analysis）
- **音频 → 特征**：
  - `librosa`：BPM、节拍、节奏型、频谱、音高轮廓、音色特征。
  - `madmom` / `essentia`：更精准的节拍、下拍、和弦识别。
  - `basic-pitch`（Spotify 开源）：音频转 MIDI，提取主旋律。
  - `demucs`：人声/伴奏分离，便于单独分析旋律与伴奏。
- **MIDI / 乐谱 → 结构**：
  - `music21`：调式、和弦、和声进行（例：I–V–vi–IV）、曲式段落。
  - 统计旋律的音程分布、跨度、方向趋势、句法（motif / 重复 / 变奏）。
- **节奏与韵律**：切分句法节奏（syncopation、swing 比例、密度）。
- **结构标注**：识别 Intro / Verse / Pre-Chorus / Chorus / Bridge / Outro。

### 2.4 风格档案（Style Card）
把上面两部分的结果，聚合成一份**结构化的可复用档案**，例如：

```yaml
song: "夜曲"
artist: "周杰伦"
lyrics:
  theme: "追忆逝去的爱人"
  narrative_pov: "第一人称"
  rhyme_scheme: "以 ang / ong 通押为主，副歌转 ao 韵"
  avg_line_syllables: 9
  rhetoric: [比喻, 拟人, 意象叠加]
  emotion_curve: [沉郁 → 悲伤 → 决绝 → 释怀]
music:
  key: "e-minor"
  tempo_bpm: 118
  time_signature: "4/4"
  form: "Intro-Verse-PreChorus-Chorus-Verse-PreChorus-Chorus-Bridge-Chorus-Outro"
  chord_progression_chorus: "i–VI–III–VII"
  melody:
    range: "b3–e5"
    contour: "副歌以级进+四度跳进为主，句尾下行"
  rhythm: "八分附点 + 十六分切分，副歌密度高"
techniques:
  - "副歌前用 Pre-Chorus 情绪堆叠"
  - "歌词意象走'雨—信—夜'的连贯符号"
  - "旋律与歌词声调基本贴合（避免倒字）"
```

这份档案既是**给人看的学习笔记**，也是**给 AI 的 prompt 素材**。

### 2.5 AI 辅助创作
- **作词**：把 Style Card 作为上下文，让 LLM（如 GPT、Claude、
  本地 Qwen / DeepSeek）在给定主题下生成歌词，并强制满足：
  韵脚方案、每句字数、段落结构、情感曲线约束。
  - 建议加一层**校验器**：生成后用 2.2 的分析器回测是否满足约束，
    不满足则自动重试或局部改写。
- **作曲 / 旋律**：
  - 基于规则 + 概率模型：用 `music21` 按和弦进行和节奏模板生成旋律骨架。
  - 基于模型：调用 **Magenta**（MusicVAE / MelodyRNN）、
    **MuseNet 类模型**、或 Suno / Udio 等在线服务生成 demo。
  - 本地开源可选：`MuseCoco`、`MusicGen`（Meta）用于伴奏/风格化生成。
- **人机协作 UI**：允许用户**局部重写**（只改副歌 / 只换和弦 / 保留旋律
  改词），而不是每次全量生成。

### 2.6 对比与学习反馈
- 把"新创作作品"与"参考曲"放在同一张 Style Card 视图下对比，
  高亮差异（韵脚命中率、和弦相似度、旋律轮廓相似度）。
- 记录用户每次"学到的技巧"，形成个人**技巧库**，可跨歌曲检索。

## 3. 技术选型建议

| 层次 | 建议方案 |
|---|---|
| 语言 | Python（分析/AI 主力）+ TypeScript（前端） |
| 后端框架 | FastAPI（轻量、异步、易接 AI） |
| 前端 | Next.js + React + Tailwind；乐谱渲染用 `VexFlow` / `OpenSheetMusicDisplay`；波形/频谱用 `wavesurfer.js` |
| 歌词分析 | `jieba`、`pypinyin`、`spaCy`、`pronouncing`、`KeyBERT`、`SnowNLP` |
| 音频分析 | `librosa`、`madmom`、`essentia`、`demucs`、`basic-pitch` |
| 乐谱/MIDI | `music21`、`pretty_midi`、`mido` |
| AI 生成 | OpenAI / Anthropic API、本地 Qwen/DeepSeek（`vLLM`/`Ollama`）、Magenta、MusicGen |
| 存储 | SQLite（MVP）→ PostgreSQL；素材文件放对象存储（S3/MinIO） |
| 任务队列 | 音频分析耗时，用 Celery / RQ + Redis 异步化 |
| 部署 | Docker Compose 起步，后续 K8s |

## 4. 系统架构（简）

```
                ┌────────────────────┐
                │      前端 UI       │  上传/搜索、Style Card、创作台
                └─────────┬──────────┘
                          │ REST / WebSocket
                ┌─────────▼──────────┐
                │   API 网关 (FastAPI)│
                └───┬─────────┬──────┘
                    │         │
        ┌───────────▼──┐   ┌──▼────────────┐
        │ 分析服务      │   │ 生成服务       │
        │ (Lyrics/Audio)│   │ (LLM + Music) │
        └───┬────────┬──┘   └──┬────────────┘
            │        │         │
       ┌────▼──┐ ┌───▼────┐ ┌──▼────────┐
       │素材库 │ │特征库  │ │作品/技巧库 │
       │(对象) │ │(DB)    │ │(DB)        │
       └───────┘ └────────┘ └────────────┘
```

数据流：**上传/输入 → 预处理（分离/OCR/抓词）→ 特征提取 → 风格档案
→ AI 生成 → 校验回测 → 人工编辑 → 沉淀入库**。

## 5. MVP 路线图（建议 4 个阶段）

### 阶段 1：最小可用（1–2 周）
- 只做**歌词分析**：粘贴中文歌词 → 输出韵脚方案、句长、情感曲线、主题总结。
- 一个"生成"按钮：给定主题 + 参考风格，调用 LLM 输出新歌词。
- 技术栈：FastAPI + 一个简单 Next.js 页面 + OpenAI/Qwen API。
- 目的：先跑通"分析 → 总结 → 生成 → 回测"的闭环。

### 阶段 2：加入音频分析
- 支持上传 mp3，用 `librosa` + `basic-pitch` 提取 BPM、调、主旋律 MIDI。
- Style Card 增加"曲"部分，前端加波形/频谱可视化。

### 阶段 3：作曲生成
- 接入 Magenta / MusicGen，生成与参考曲同风格的旋律或伴奏 demo。
- 支持"只重生成副歌"等局部操作。

### 阶段 4：学习闭环
- 个人技巧库、跨歌曲检索、A/B 对比、导出乐谱 PDF / MIDI。
- 可选：社区分享 Style Card。

## 6. 关键落地建议

1. **先做闭环，再做深度**：不要一上来就啃音频分析。先用"歌词 + LLM"
   跑通"分析→总结→生成→评估"的循环，你会最快学到东西。
2. **让分析器也当校验器**：AI 生成的东西一定要用**同一套分析规则**回测
   （押韵是否命中、字数是否达标、和弦是否符合），形成自动迭代。
3. **Style Card 是核心资产**：它同时服务"人类学习"和"AI prompt"，
   要设计成结构化 YAML/JSON，方便版本化和 diff。
4. **约束式生成优于自由生成**：给 LLM 明确的"韵脚 / 字数 / 段落 / 情感
   曲线"约束，产出质量会好一个数量级。
5. **保留人工介入点**：创作是"人机协作"，UI 要允许逐句锁定、局部重写。
6. **本地 + 云混合**：文本可用云端大模型；音频类模型体积大、隐私敏感，
   建议本地推理（`Ollama` / `MusicGen` local）。

## 7. 版权与合规提示（重要）

- **歌词/音频抓取**：直接从网易云、QQ 音乐等抓歌词/音频用于**再分发**
  会侵权。个人学习用途下，建议：
  - 让用户**自行上传**已合法获得的音频/歌词。
  - 或只保存**分析结果（特征）**，不保存原始音频/完整歌词。
- **AI 生成物**：
  - 不要让模型直接**复述**训练素材的原句；生成后建议做**相似度检测**
    （对歌词做 n-gram 重叠检查，对旋律做 pitch-contour 相似度检查）。
  - 明确标注"AI 辅助创作"。
- **模型许可**：留意 MusicGen、Demucs、Magenta 等的开源协议
  （多为研究/非商用友好，商用需确认）。

## 8. 下一步

如果同意这个方向，建议下一次迭代直接进入 **阶段 1 MVP**：

- 在仓库里创建 `backend/`（FastAPI）和 `frontend/`（Next.js）两个骨架。
- 实现 `POST /analyze/lyrics`：输入中文歌词，返回 Style Card JSON。
- 实现 `POST /generate/lyrics`：输入主题 + Style Card，返回新歌词，
  并附上"回测报告"（韵脚命中率、字数达标率等）。

之后再按阶段 2–4 增量扩展。
